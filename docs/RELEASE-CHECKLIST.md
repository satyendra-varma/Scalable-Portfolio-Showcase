# Release checklist

Unchecked means not yet verified.

## Content and privacy

- [ ] Owner-approved positioning and selected visual direction.
- [ ] Claims checked against resume; no invented project details or diagram topology.
- [ ] Business Operations contains only approved resume-level information.
- [ ] Missing project links omitted; real links checked when supplied.
- [ ] Public PDF reviewed visually and via text/metadata extraction.
- [ ] Phone absent from public content, bundles, AI knowledge and downloadable assets.
- [ ] Raw uploads are not publicly served.
- [ ] Email, LinkedIn, and location match approved sources.

## Functionality and safety

- [ ] Routes, deep links, contact and downloads work.
- [ ] AI provider configured server-side; no credentials in public bundles.
- [ ] Supported answers have valid citations; unsupported questions refuse.
- [ ] Input, timeout, rate, concurrency and deployment-instance limits verified.
- [ ] Transcript/body logging disabled; provider processing/retention disclosed accurately.
- [ ] Provider outage leaves core portfolio usable.
- [ ] Automated unit/integration/browser tests run with results recorded.
- [ ] Keyboard, contrast, reduced-motion and mobile checks completed.
- [ ] Performance measured; failed budgets or limitations documented.

## Publishing

- [ ] Backend/runtime/publishing compatibility confirmed.
- [ ] Owner approves publishing.
- [ ] Obtain actual published URL and configure canonical/social/sitemap URLs.
- [ ] Verify live navigation, deep-link reload, resume, project links, and ambassador.
- [ ] Review restore/checkpoint approach for a failed release.
